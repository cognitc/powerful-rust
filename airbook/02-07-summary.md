# Итоги: Rust заставляет думать

Вы прочитали шесть глав о "базовых" вещах
То, что в других языках проходят за час, здесь растянуто на целый модуль
Не потому что Rust сложный, а потому что он требует явно указывать намерения

## Комментарии: документируйте намерения, не очевидности

Код на Rust благодаря типизации часто говорит сам за себя
Ваши комментарии должны объяснять **почему**
Используйте `TODO` и `FIXME` как якоря для технического долга

## Переменные: неизменяемость по умолчанию

Неизменяемость это контракт
`let x = 5` означает "x всегда будет 5"
Если нужно изменение, то явно попросите через `mut`
Это ловит баги на этапе компиляции, а не на проде

`const` это константа времени компиляции, видна везде, тип обязателен
Затенение (`let x = ...; let x = ...`) это создание новой переменной
с тем же именем

### Типы: паранойя, которая спасает

Rust не доверяет вам с числами и правильно делает
Переполнение в debug паникует, в release "заворачивается"
Плавающая точка неточна по определению,
поэтому **никогда** не используйте `f64` для денег

Что использовать по умолчаниию

- Целые `i32`
- Дробные `f64`
- Индексы `usize`

### Составные типы: группировка без кучи

Кортежи `(T, U)` для разнородных данных,
массивы `[T; N]` для однородных фиксированного размера
Оба на стеке, оба с проверкой границ
Массив `[i32; 5]` и `[i32; 6]` это разные типы,
помните об этом при проектировании функций

### Функции: всё является выражением

Последняя строка без точки с запятой это возвращаемое значение
Блоки `{}` тоже выражения
`if` и `match` -- выражения
Это меняет мышление с "делай это, потом это" на "вычисли значение через композицию"

Если функция что-то возвращает, то нет точки с запятой в конце
Если поставили, то получите `()` вместо ожидаемого значения

### Управляющие конструкции: явное лучше неявного

- `if` требует строго `bool`
- обе ветки `if` должны вернуть один тип
- `loop` может возвращать значение через `break value`
- `for` по итераторам безопаснее и быстрее чем `while` по индексам

## Главный вывод: компилятор ваш напарник, не враг

В Python или JavaScript вы пишете код, запускаете, ловите баги, чините
В Rust вы **сначала думаете**, потом пишете,
и компилятор проверяет ваши рассуждения
Это медленнее в начале, но быстрее в перспективе потому что баги,
которые не прошли компиляцию, не уйдут к пользователям

Эти "скучные" основы являются фундаментом для системы владения, заимствований,
многопоточности и безопасной работы с памятью
Без понимания, почему `let mut` требует явного разрешения,
вы не поймёте, почему borrow checker такой придирчивый
