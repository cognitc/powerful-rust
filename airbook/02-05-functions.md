# Функции: кирпичики вашего кода

Если вы программировали на Python или JavaScript, функции в Rust
покажутся одновременно родными и немного странными
Да, здесь тоже есть `fn`, параметры и возвращаемые значения как и везде
Но в Rust есть свои особенности

Поехали разбирать, почему компилятор такой придирчивый к функциям

## Базовый синтаксис: змеиный стиль

Мы определяем функцию в Rust, вводя `fn`, затем имя функции и
параметры в круглых скобках
Фигурные скобки указывают компилятору, где начинается и заканчивается тело функции

В Rust используется `snake_case` для названий функций, все буквы маленькие,
а слова через подчёркивание
Не `doSomething`, а `do_something`
Не `processData`, а `process_data`
Компилятор не укусит за `CamelCase`, но коллеги да

```rust
fn main() {
    do_work();
}

fn do_work() {
    println!("Работаем...");
}
```

Rust не важен порядок определения функций
Функция `do_work` может быть написана до `main`, после, или вообще в другом файле
Главное, чтобы она была видна в текущей области видимости
когда до неё доходит очередь компиляции
Это мелочь, но приятная: не нужно делать forward declaration как в C

## Параметры: никакой автоматики, только хардкор

Мы можем определять функции с **параметрами** -- специальными переменными,
которые являются частью сигнатуры функции
Когда у функции есть параметры, вы можете предоставить ей
конкретные значения для этих параметров
Технически конкретные значения называются **аргументами**,
но в неформальной беседе слова *параметр* и **аргумент**
часто используют взаимозаменяемо для переменных в определении функции
или конкретных значений, передаваемых при вызове

Вот где начинается "боль Rust"
Вы **обязаны** указать тип каждого параметра
Никаких "компилятор же догадается"
Нет, не догадается, и он настаивает:

```rust
// Правильно
fn calculate(x: i32, y: f64) -> f64 {
    x as f64 + y
}

// Неправильно -- не скомпилируется
fn calculate(x, y) { ... }
```

Звучит душно?
На самом деле это экономит часы дебага
Когда вы читаете чужой код через полгода, вы точно знаете:
`x` целое число, а `y` дробное
Никаких сюрпризов вроде "а вдруг туда строку передали".

```rust
fn print_measurement(value: i32, unit: char) {
    println!("Измерение: {value}{unit}");
}

fn main() {
    // Код выведет 5h
    print_measurement(5, 'h');
}
```

## Инструкции (Statements) и выражения (Expressions): настоящая "магия" Rust

В Rust функции построены на **выражениях** (expressions),
а не **инструкциях** (statements)
Это меняет всё

**Statement (инструкция)** делает что-то, но не возвращает значение
Как `let x = 5;`
Это приказ "создай переменную", а не значение, которое можно использовать

**Expression (выражение)** вычисляется в значение
Пример: `5 + 6` (даёт 11), или вызов функции, или... блок кода в фигурных скобках!

Вот что сводит с ума новичков:

```rust
fn main() {
    let x = {
        let a = 3;
        // Нет точки с запятой!
        a + 1
    };
    // 4
    println!("{}", x);
}
```

Блок `{ ... }` это выражение, которое возвращает последнюю строчку
Если поставить точку с запятой после `a + 1`,
вы получите `()` (юнит тип, ничто)
Без точки с запятой получите `4`

Это работает везде
В том числе и в функциях

## Блоки как области видимости

Внутри функции можно создавать блоки -- временные зоны, чтобы не засорять namespace:

```rust
fn complex_calculation() -> i32 {
    let x = {
        let temp = 5;
        let bonus = 3;
        temp * bonus
    };
    // temp и bonus умерли здесь, их имена свободны
    
    let y = {
        // Можно снова использовать имя temp!
        let temp = 10;
        temp + 2
    };
    
    // 17
    x + y
}
```

Это спасает от адских спагетти с именами вроде `temp1`, `temp2`, `final_temp`

## Что возвращает функция, если ничего не указано?

```rust
fn say_hello() {
    println!("Привет!");
}
```

Эта функция на самом деле возвращает `()`
Это "юнит тип", пустой кортеж, тип с одним значением -- пустотой
Он аналогичен `void` в C, но это не "отсутствие типа", а конкретный тип
Это важно для обобщённого программирования, когда пишите код,
который работает одинаково с функциями, возвращающими значения,
и с функциями без возврата значений

## Возвращаемые значения: когда решает последняя строчка

В Rust нет привычного `return` в конце
(хотя его можно использовать для раннего выхода)
Функция просто возвращает значение последнего выражения:

```rust
fn five() -> i32 {
    // Вот и всё
    // Не "return 5;", а просто "5" висящая в ВОЗДУХЕ
    5
}

fn main() {
    let x = five();
    // 5
    println!("{}", x);
}
```

Выглядит странно? Ну да, а щито поделать
Привыкнете
Предпологается, что это заставляет писать функции как цепочки вычислений,
а не последовательности команд

Но вот ловушка, в которую каждый новичок наступает как минимум раз:

```rust
fn plus_one(x: i32) -> i32 {
    // ЗАВЕРШАЕТСЯ ТОЧКОЙ С ЗАПЯТОЙ!
    x + 1;
}
```

Компилятор устроит истерику: `expected i32, found ()`
Точка с запятой превратила выражение `x + 1` в инструкцию
Инструкция ничего не возвращает (на самом деле возвращает `()`)
А мы обещали вернуть `i32`

Правильно так:

```rust
fn plus_one(x: i32) -> i32 {
    // Никакой точки с запятой в конце!
    // Просто значение
    x + 1
}
```

## Ранний выход: return допустим, но не приветствуется

Можно написать так:

```rust
fn check_age(age: i32) -> &'static str {
    if age < 0 {
        return "Ты из будущего?";
    }
    if age > 150 {
        return "Ты вампир?";
    }
    // Основной путь без return
    "Всё ок"
}
```

Это работает
Но в Rust-сообществе такой стиль считается "императивным", процедурным
Идеологически правильнее писать через match или if-выражения,
где один вход один выход
Но для валидации входных данных или guard clauses `return` вполне ок

## Пример, где всё собрано воедино

```rust
fn calculate_price(amount: i32, unit_price: f64) -> f64 {
    let base = amount as f64 * unit_price;
    
    let coefficient = if amount > 100 {
        // Скидка 10%
        0.9
    } else if amount > 500 {
        // Скидка 20%
        0.8
    } else {
        // Без скидки
        1.0
    };
    
    // Результат, без return и без ;
    base * coefficient
}

fn main() {
    let total = calculate_price(150, 10.0);
    // 1350.0
    println!("К оплате: {} руб.", total);
}
```

Здесь всё: явные типы параметров,
`if` как выражение (да, он возвращает значение!),
и неявный return последней операции.
Код читается как математическая формула:
"итог равен цене умноженной на коэффициент"

**Запомните главное:**

- Начинайте писать функцию с `fn`
- Указывай типы параметров явно
- Если функция что-то возвращает не ставьте точку с запятой в конце последней строки
- Если не возвращает вообще не пишите `-> Type`.
- Используйте блоки `{}` для временных вычислений, чтобы не плодить переменные
