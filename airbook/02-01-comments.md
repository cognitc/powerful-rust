# Комментарии: письмо для будущего себя из прошлого

Комментарии -- единственное, что компилятор игнорирует полностью.
Не проверяет, не анализирует, не оптимизирует.
Для него их нет.

Но для вас через полгода, когда вы будете читать этот код как чужой,
комментарии станут спасательным кругом.
Или якорем, если написаны плохо.

## Базовый синтаксис: придерживайтесь `//`

Стандартный комментарий начинается с `//` и действует до конца строки:

```rust
// Это комментарий. Компилятор пропустит эту строку полностью
```

Если нужно несколько строк, просто повторяйте `//` для каждой.
Да, это немного утомительно, но так принято:

```rust
// Здесь мы делаем что-то сложное, требующее длинного объяснения
// Надеюсь, комментарий прояснит ситуацию
let result = complex_calculation();
```

Можно использовать и `/* ... */`, как в C:

```rust
/* Многострочный комментарий
   тоже работает, но */
```

Но в сообществе Rust такой стиль не приветствуется.
Он мешает при комментировании кусков кода для отладки.
Вы не можете закомментировать кусок кода, который уже содержит `/* */`,
да и читается при беглом осмотре хуже.
Придерживайтесь `//` -- это уже стандарт де-факто.

## Где ставить: над кодом или в конце строки?

Технически оба варианта работают:

```rust
let tax_rate = 0.13; // 13% НДФЛ

// 13% НДФЛ
let tax_rate = 0.13;
```

Но идиоматично оставлять комментарий **над** кодом.
Так читается легче: сначала контекст, потом действие.
Потому что мы читаем код сверху вниз.
Используйте конец строки только для коротких пометок
про магические числа или временные костыли.

## Когда комментировать

Вот ловушка, в которую попадают все начинающие программисты.
Они пишут:

```rust
// Проверяем, что возраст больше 18
if user.age > 18 {
    allow_access();
}
```

Это бесполезно.
Код и так говорит, что он делает.
Комментарий должен объяснять **почему**:

```rust
// Требование легализации: доступ к контенту 18+
// только после проверки паспорта (п. 4.2 бизнес-требований)
if user.age > 18 && user.passport_verified {
    allow_access();
}
```

Или когда код не может быть очевидным по определению:

```rust
// Округляем вверх, потому что бухгалтерия хочет "с запасом"
// Да, это странно, но так написано в договоре от 2019 года (ticket #2345)
let tax = amount.mul(rate).ceil();
```

## Комментируйте костыли

Единственный случай, когда комментарий "что делает" оправдан,
временные решения (костыли):

```rust
// FIXME: костыль для бага в библиотеке XYZ версии 0.8
// Убрать после обновления до 0.9
// См. issue #42: https://github.com/...
let workaround = calculate_workaround();
```

Такие комментарии с тегами вроде `TODO`, `FIXME` позволяют быстро находить
технический долг через `grep` или поиск в IDE.

```bash
grep -r "TODO" src/
```

## Rust vs другие языки: нужно ли меньше комментариев?

Здесь Rust вас удивит.
Благодаря строгой типизации и самодокументирующимся сигнатурам,
хороший код на Rust часто содержит меньше комментариев,
чем эквивалент на Python или JavaScript.

Сравните:

```python
# user_id -- число или строка? Может быть None?
# Вернёт словарь с данными или None, или бросит исключение?
def find_user(user_id):
```

```rust
// Rust: типы говорят сами за себя
fn find_user(id: u64) -> Option<User>
```

В Rust типы и имена параметров несут огромную смысловую нагрузку
Если ваша функция называется `calculate_tax`, то не надо писать.

```rust
// Функция расчёта налога
fn calculate_tax(amount: f64, rate: f64) -> f64 {
    // ...
}
```

Это и так очевидно.

## Документация != комментарии

Комментарии вида `//` для тех, кто читает код.
Но есть комментарии `///` и `//!`, для создания документации
которые компилятор не игнорирует, а превращает в HTML страницы.

```rust
/// Проверяет контрольную сумму карты по алгоритму Луна
///
/// Алгоритм Луна -- простая формула контрольной суммы для валидации
/// различных идентификационных номеров: кредитных карт, IMEI, SSN.
///
/// # Аргументы
///
/// * `number` -- строка с цифрами. Пробелы и дефисы игнорируются.
///
/// # Возвращает
///
/// `true` если номер проходит проверку, `false` в противном случае.
///
/// # Примеры
///
/// ```
/// assert!(is_valid_card("2201382000000013"));       // МИР
/// assert!(is_valid_card("4111 1111 1111 1111"));    // VISA через пробел
/// assert!(is_valid_card("5555-5555-5555-4444"));    // MasterCard с дефисами
/// assert!(!is_valid_card("1234567890123456"));      // невалидный номер
/// ```
fn is_valid_card(number: &str) -> bool {
    // ...
}
```

О них поговорим позже в главе про публикацию своих библиотек.
Пока просто знайте: если пишете `///` вместо `//`, вы пишете документацию,
а не заметку на полях.

## Заключение

Комментарий это признание, что код сам не может объяснить намерения.
Сначала попробуйте переименовать переменную или разбить функцию на части.
Если всё ещё непонятно -- тогда комментируйте.
И всегда помните: через полгода вы будете читать этот код как чужой.

Теперь, когда мы разобрались с комментариями,
давайте перейдём к самому коду -- и первое, что бросается в глаза в Rust,
это необычное поведение переменных.
