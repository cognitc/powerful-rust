# Типы данных: Rust -- язык параноика и это замечательно

Rust -- язык со статической типизацией
Перевод на человеческий: компилятор хочет знать, что лежит в каждой переменной,
ещё до запуска программы
Не во время выполнения, когда всё уже сломалось,
а заранее, когда ещё можно исправить ошибку

Если вы пришли из Python или JavaScript, первое время вас будет бесить
необходимость объяснять компилятору, что же такое `x`
Не просто "дайте мне переменную", а именно: "это беззнаковое 32-битное целое,
которое я буду использовать для индексов"

Но Rust умеет выводить типы, когда может:

```rust
// i32 по умолчанию, компилятор догадался
let x = 5;
```

Проблемы начинаются, когда вариантов много:

```rust
// ОШИБКА!
// Какой тип?
// i32? u64? i128?
let guess = "42".parse().unwrap();
```

Нужно сказать явно через аннотацию:

```rust
let guess: u32 = "42".parse().unwrap();
```

или через turbofish

```rust
let guess = "42".parse::<u32>().unwrap();
```

Это раздражает, но спасает, когда пользователь вводит "два" вместо "2"

## Скалярные типы: атомы данных

Скалярные типы это неделимые атомы для хранения данных,
они хранят только 1 значение
Всего их 4 вида: целые числа, числа с плавающей точкой,
логические значения и символы
Если вы уже знакомы с другими языками
программирования, эти типы покажутся вам знакомыми,
но в Rust у каждого есть свои особенности

## Целые числа: выбирайте размер разумно

Целое число -- число без дробной части

Вот таблица, которую невозможно запомнить с первого раза:

| Размер                 | Знаковое | Беззнаковое |
| ---------------------- | -------- | ----------- |
| 8 бит                  | `i8`     | `u8`        |
| 16 бит                 | `i16`    | `u16`       |
| 32 бит                 | `i32`    | `u32`       |
| 64 бит                 | `i64`    | `u64`       |
| 128 бит                | `i128`   | `u128`      |
| архитектурно-зависимое | `isize`  | `usize`     |

Разница между `i` (signed) и `u` (unsigned) простая:
`i8` хранит от -128 до 127, а `u8` от 0 до 255
Если вы считаете предметы, берите `u32` (отрицательных предметов не бывает)
Если температуру, то `i32` (может быть минус)

- Знаковые (i): от −(2^(n−1)) до 2^(n−1) − 1
- Беззнаковые (u): от 0 до 2^n − 1  

Это как запись чисел на бумаге:
когда знак важен, число пишется со знаком `+` или `-`
если считать число положительным, знак не указывается

Не знаете что выбрать -- берите `i32`
Это работает в большинстве случаев

- `isize`/`usize` нужны для индексов массивов и счётчиков
Они равны разрядности процессора: 32 на 32-битных системах и 64 на современных
- `u8` для сырых байтов (передача данных по сети, цвета RGB)

Важно: i и u несовместимы между собой
Нельзя просто сложить i32 и u32, нужно явно приводить типы:

```rust
let a: i32 = -5;
let b: u32 = 10;
// b приводим к i32
let c = a + b as i32;
```

Литерал это фиксированное значение, записанное прямо в коде
(например,  42 ,  "hello"  или  true ),
которое неизменно и известно уже на этапе компиляции

В Rust можно визуально разделять числа через символ `_`, который используется
для улучшения читаемости больших числовых литералов:

```rust
// Вместо 1000000
let million = 1_000_000;
// Вместо 1000000000
let billion = 1_000_000_000_i64;
```

Ключевые моменты:

- Подчёркивание игнорируется компилятором, оно только для человека
- Можно ставить в любом месте между цифрами (но не в начале/конце)
- Работает со всеми числовыми типами

Литералы можно писать в разных системах счисления:

```rust
// 255 в шестнадцатеричной
let hex = 0xff;
// 63 в восьмеричной
let octal = 0o77;
// 240, подчёркивание для читаемости
let binary = 0b1111_0000;
// u8, только для ASCII
let byte = b'A';
```

## Переполнение: тихий убийца

Вот где Rust показывает свой двуликий характер
У вас есть `u8` (максимум 255). Вы прибавляете 1 к 255
Что произойдёт?

В режиме разработки (debug):
программа паникует и падает
Явно, громко, с сообщением об ошибке

В релизе (--release):
происходит "заворачивание" (wrapping)
256 становится 0, 257 -- 1, и так далее
Тихо. Без предупреждений
Ваши расчёты рассыпаются, но программа продолжает работать с мусором
как ни в чём не бывало

В 1996 году ракета Ariane 5 взорвалась из-за переполнения
64-битного числа при конвертации в 16-битное
Ущерб полмиллиарда долларов
Rust не даст вам так легко выстрелить себе в ногу в debug-режиме, но не в релизе

Если вы пишете код, где переполнение == катастрофа, используйте явные методы:

```rust
let x: u8 = 255;

// Заворачивание (то, что происходит в релизе)
// Будет 0
let wrapped = x.wrapping_add(1);

// Насыщение (остаётся на максимуме/минимуме)
// Будет 255
let saturated = x.saturating_add(1);  // 255

// Проверка было ли переполнение (возвращает Option)
let w = x.checked_add(1);
```

## Плавающая точка: деньги нельзя

Два типа: `f32` (32 бита) и `f64` (64 бита)
По умолчанию `f64`, потому что на современных процессорах он работает так же быстро
или быстрее из-за меньшего количества преобразований, но точнее
Все типы с плавающей точкой являются знаковыми

```rust
// f64, по умолчанию
let x = 2.0;
// f32, явно указали
let y: f32 = 3.0;
```

Запомните раз и навсегда:
`0.1 + 0.2 != 0.3` в IEEE-754

```rust
fn main() {
    // 0.30000000000000004000
    println!("{:.20}", 0.1 + 0.2);
    // false. ДА, FALSE
    println!("{}", 0.1 + 0.2 == 0.3);
```

Это не баг Rust, это математика двоичной плавающей точки

Почему?
IEEE 754 -- стандарт представления чисел с плавающей точкой
Он работает в двоичной системе
Десятичные дроби вроде `0.1` не имеют конечного двоичного представления

Никогда не проверяйте равенство напрямую:

```rust
// Неправильно
if x == 0.3 { 
    ...
}

// Правильно
// Сравниваем с учётом погрешности
let epsilon = 1e-10;
if (x - 0.3).abs() < epsilon { 
    ...
}
```

К чему приводят ошибки округления
Немецкий розничный банк использовал стандартную арифметику с плавающей точкой
для расчета сложных процентов по ипотеке
Накопленные ошибки округления привели к тому,
что некоторые клиенты переплатили сотни евро, а другие наоборот недоплатили
За 5 лет накопилась суммарная ошибка в 12 миллионов евро

А в 1991 году Patriot Missile не перехватил ракету
из-за накопленной ошибки округления в floating-point счётчике времени
Погибли 28 человек

Это одна из причин, почему финансовый софт пишут с особой осторожностью
Для денег никогда не используйте стандартные типы
Никогда
Только специальные библиотеки вроде `rust_decimal` или `bigdecimal`

Как это работает?
Допустим, нужно сохранить сумму 253.52 рубля
Вместо того что бы хранить как есть, мы можем представить эту сумму
сразу в копейках просто умножив на 100
Получим целое число 25 352 и никакие погрешности нам не страшны

## Числовые операции

Rust поддерживает базовые математические операции для всех числовых типов:
сложение, вычитание, умножение, деление и остаток
Но есть нюанс с целочисленным делением, оно округляет к нулю до ближайшего целого

## Логический тип

Логический тип в Rust задается с помощью `bool`

Как и в большинстве языков, имеет два возможных значения: `true` или `false`
Логические значения занимают 1 байт, а не 1 бит как могло бы показаться

Почему не 1 бит?
Из-за выравнивания (alignment)
Современные CPU читают память по адресам,
кратным нескольким байтам (обычно 4 или 8)
Если бы `bool` был 1 битом, CPU приходилось бы делать сложные операции
для извлечения этого бита
1 байт это компромисс между памятью и скоростью доступа

Основной способ использования логических значений в условиях,
например в выражении `if`:

```rust
if user.is_premium {
    // ...
}
```

## Символьный тип

Тип `char` самый простой алфавитный тип
`char` это всегда 4 байта UTF-32
Это не один байт, как в C, и не переменное количество байт, как в строках

Это значит, что вы можете написать:

```rust
let c = 'z';
let z = 'ℤ';
let emoji = '😻';
```

Символ, который видит пользователь(grapheme cluster)
может состоять из нескольких `char`

Пример:
Флаг страны 🇯🇵 -- это два `char`, соединённых вместе

`char` это техническая единица, а не лингвистическая
Если вам нужно работать с "буквами как видит пользователь",
используйте крейт `unicode-segmentation`, а не стандартный `char`
