# Переменные и изменяемость

Вот что вызывает первую волну злости у новичков
Вы пишете код, который сработал бы в Python, JavaScript, C++, да где угодно:

```rust
fn main() {
    let x = 5;
    println!("x = {x}");
    // ОШИБКА!
    x = 10;
    println!("x = {x}");
}
```

При попытке скомпилировать программу, вы получите красноречивый мат от компилятора:

```console
error[E0384]: cannot assign twice to immutable variable `x`
```

"Нельзя присвоить значение дважды неизменяемой переменной!"

Ваш мозг коротит:
"Что значит неизменяемой? Я же только что создал переменную!
Переменные созданы для того, чтобы меняться! Это буквально есть в названии!"

Tерпите. Это не баг. Это то, из-за чего Rust вообще стоит изучать

## Неизменяемость по умолчанию

Переменные в Rust по умолчанию неизменяемы
Это одна из многих особенностей Rust, которая сразу приучает писать
правильный код без утечек памяти и гонок данных

Когда вы пишете `let x = 5`, вы говорите:
"Я обещаю, что x всегда будет 5. Никаких сюрпризов"

Компилятор Rust берёт эту рутину на себя:
если вы сказали, что значение неизменно, он этого и будет придерживаться
Это как контракт, подписанный кровью ещё до запуска программы

## Зачем такие заморочки?

Представьте: у вас есть переменная, которая принимает настройки и рассчитывает,
что те не изменятся:

```rust
// Где-то в начале программы
let config = load_config();

// Где-то в глубине функции обработки
// 10 000 строк кода спустя
// Ой, мы поменяли глобальную конфигурацию
config.limit = 10;
```

Без неизменяемости такое проходит молча
Потом вы три часа ищите, почему программа ведёт себя странно,
пока не обнаружите, что где-то в недрах кода кто-то "случайно" подменил настройки

## Как с этим жить? Добавим ключевое слово `mut`

Но иногда изменять переменные нужно
Rust просто требует явного разрешения

Вернитесь к коду и добавьте три буквы `mut`:

```rust
fn main() {
    // Теперь можно изменять x
    let mut x = 5;
    println!("x == {x}");
    // ОК, вы предупреждали, что будете менять x
    x = 10;
    println!("x == {x}");
}
```

Теперь всё работает
`mut` (от mutable) это не просто ключевое слово
Это сигнал для всех, кто будет читать ваш код:
"Внимание, эта штука будет меняться! Следи за ней глазками!"

Советую начинать без `mut`, и добавлять его только тогда, когда компилятор требует
или заранее известно что переменная точно будет меняться

## Запретная зона

Попробуйте создать переменную с названием `let` или `fn`:

```rust
// error: expected identifier, found keyword `let`
let let = 5;
```

В Rust около 50 зарезервированных слов -- `mut`, `if`, `match`, `return` и так далее
На старте просто запомните: если компилятор странно ругается на имя переменной,
проверьте, не попало ли оно в черный список

Самые частые ловушки: `type`, `ref`, `box`, `where`
Да, иногда хочется назвать переменную `type`, но придётся придумать
что-то вроде `kind` или `connection_type`

## Константы это не то же самое, что неизменяемые переменные

Есть ещё один способ объявить неизменяемое значение и это `const`
Как и неизменяемые переменные, **константы** это значения, связанные с именем,
которые нельзя изменить

```rust
const MAX_PLAYERS: u32 = 100;
const PI: f64 = 3.14159;
const WAIT_SECONDS: u32 = 60 * 60 * 3;
```

И нет, это не просто `let` с заглавными буквами
Это совсем другой зверь:

- Никакого `mut`. Совсем. Константы вечны как император
- Тип обязателен. Компилятор не будет угадывать, что там у вас хранится
- Видны везде. Можно объявить в начале файла и использовать в любой функции
- Значение вычисляется на этапе компиляции
Только константные выражения, никаких `read_file()` или `rand()`

```rust
const WAIT_SECONDS: u32 = 60 * 60 * 3;
```

Почему тут `60 * 60 * 3`, а не просто `10800`?
Когда требования изменятся на 5 часов, вы поймёте,
что нужно менять без проверки на калькуляторе

## Затенение (Shadowing): магия или безумие?

В Rust можно использовать одно имя для разных значений, даже разных типов:

```rust
fn main() {
    let x = 5;
    // Та же буква 'x', но новая переменная!
    let x = x + 1;
    
    {
        // и снова новая 'x', но уже внутри блока
        let x = x * 2;
        // 12
        println!("Внутри: {x}");
    }
    // 6
    println!("Снаружи: {x}");
}
```

Это называется затенение
Первая `x` прячется за второй, вторая за третьей
Когда внутренний блок заканчивается, "всплывает" предыдущая версия
Каждый `let` создает новую переменную, которая "закрывает" собой старую
Старая не удаляется -- она просто становится недоступной пока перекрывается

## Зачем это нужно?

Представьте типичный сценарий обработки ввода:

```rust
// Строка с пробелами
let input = "   42   ";
// Строка без пробелов "42"
let input = input.trim();
// Число 42
let input: u32 = input.parse().unwrap();
```

Без затенения пришлось бы изобретать имена: `input_raw`, `input_trimmed`, `input_parsed`
С затенением код читается как история: "сначала это было текстом, потом стало числом"

Не путайте с `mut`!
Здесь вы создаете совершенно новую переменную в памяти,
а старая прячется в тени до конца блока

Если попробовать тот же трюк с `mut`:

```rust
let mut spaces = "   ";
// ОШИБКА! А тип то не тот! Ожидали &str, а получили usize
spaces = spaces.len();
```

С `mut` вы меняете значение, но тип остаётся
С `let` вы создаёте совершенно новую переменную,
которая просто использует старое имя
