# Составные типы: группировка данных

Одиночные числа и символы -- это хорошо, но реальный мир сложнее
У пользователя есть имя, возраст и статус активности
У точки на экране есть X и Y
У HTTP-ответа есть код статуса, заголовки и тело

Составные типы могут группировать в себе несколько значений

Rust предлагает два способа группировать данные без кучи
и без сложных структур: кортежи и массивы
Оба живут на стеке,
оба имеют фиксированный размер, известный при компиляции

## Кортежи (Tuple)

Кортеж -- это коробка, в которую вы накидали разные вещи,
закрыли крышку, и теперь они там лежат вместе
Размер фиксирован, но типы элементов могут отличаться

```rust
// (&str, i32, bool)
let user = ("Alice", 30, true);
```

Доступ либо по индексу через точку (да, точка, не квадратные скобки!),
либо деструктуризацией:

```rust
// По индексу
let name = user.0;
let age = user.1;

// Деструктуризация
let (name, age, is_active) = user;
```

Кортежи удобны, когда функция должна вернуть несколько значений без создания структуры:

```rust
fn get_user() -> (String, u32) {
    ("Alice".to_string(), 30)
}
```

### Юнит-тип `()`

Есть специальный пустой кортеж
Он называется "юнит" (unit) и пишется как `()`
Это аналог `void` в C, но в Rust это не "отсутствие типа", а тип,
имеющий ровно одно значение -- пустой кортеж

Каждая функция в Rust что-то возвращает
Если вы не указали тип возврата и не вернули значение явно,
компилятор подставляет `()`
Это важно для обобщённого программирования: можно написать код,
который работает одинаково с функциями, возвращающими значения,
и с функциями, ничего не возвращающими, потому что `()` это тоже значение

```rust
// Эта функция на самом деле возвращает ()
fn say_hello() {
    println!("Привет!");
}
```

## Массивы: стековые коллекции фиксированного размера

Если кортеж это коробка с разным барахлом,
то массив это лоток для яиц
Все элементы одного типа, размер известен при компиляции и никогда не меняется

```rust
// [тип; размер] -- [i32; 5]
let scores = [85, 90, 78, 92, 88];

// Инициализация с повторением значения
// [значение; количество]
// 1 000 нулей
let zeros = [0; 1000];
```

Но вот что круто в Rust так это проверка границ
В C/C++ такой код скомпилируется и или выстрелит в ногу, или даст мусор:

```c
int arr[5] = { 1, 2, 3, 4, 5 };
// undefined behavior, чтение чужой памяти
printf("%d", arr[10]);
```

В Rust:

```rust
let arr = [1, 2, 3, 4, 5];
// Ошибка 'index out of bounds'
println!("{}", arr[10]);
```

Программа упадёт сразу и громко, а не тихо порчит память
В режиме `--release` проверка границ остаётся (в отличие от некоторых других проверок),
потому что это слишком важно для безопасКонечно, пности

Проверка на каждом доступе это накладные расходы
Если вы пишете критичный к скорости код и можете гарантировать безопасность индексов
(например, цикл по массиву с известными границами),
компилятор часто оптимизирует проверки
Но если вы используете индекс, полученный от пользователя проверка останется,
и это хорошо

Используйте массивы, когда:

- Размер известен при компиляции и никогда не меняется
(дни недели, месяцы, матрица 3x3 для 3D-трансформации)
- Вам важна производительность и отсутствие аллокаций на куче
- Вы работаете с данными в виде пакетов фиксированной длинны

Например,

```rust
let months = ["Январь", "Февраль", "Март", "Апрель", "Май", "Июнь", "Июль",
              "Август", "Сентябрь", "Октябрь", "Ноябрь", "Декабрь"];
```

Размер массива это часть его типа
`[i32; 5]` и `[i32; 6]`  разные типы
Вы не можете написать функцию, которая принимает "массив любой длины", как в C:

```rust
// ОШИБКА: размер должен быть известен
fn print_array(arr: [i32]) {
    ...
}
```
